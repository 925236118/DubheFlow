# DubheFlow · 天枢

> **天枢**(Tianshu),北斗七星之首(大熊座 α,Dubhe)。「枢」为门户转轴,取意本工作站是整个游戏项目的**中枢**——统管策划、美术、程序、音频、测试各个方向,把分散的模型、工具、流程收拢到一处。

## 项目愿景

DubheFlow 是一个面向 **Godot 游戏开发**的本地优先、可视化、多 Agent 一体化工作站。它定位于一个**开发中枢**——让用户可以基于「天枢工作流」**生成工作流程并执行**,而不仅仅是调用单个 AI 模型。

围绕一条核心闭环展开:**生成流程 → 执行流程 → 验证产出**。

在这个中枢里,用户能够:

- **管理** —— 统一编排策划、美术、程序、音频、测试等各方向的流程,把分散的模型与工具收拢到一处。
- **生产** —— 与 AI 对话即可实时生成一条流水线(spec),或手工在画布上拖拽编排;两者产出同一份可复用的工作流。
- **验证** —— 规则优先、小模型兜底,对每一步产出做自动裁决(语法检查、冒烟测试、断言、必要时多模态审查),而不是靠人肉查看。
- **自定义工作流** —— 工作流不可变版本化,运行钉住具体 revision,可复现、可回退;满意的流程蒸馏成模板,用得越久,现场生成的比例越低。
- **按自己习惯打造工具** —— 接入一个服务(填一次 key)即自动获得一批节点;Godot 作为本地服务同等接入。换模型、换厂商,工作流一个字不用改。

## 设计原则

1. **规则优先,小模型兜底,大模型执行。** 能用规则判定的不调模型,模糊情况才交给模型。
2. **候选意图、可用节点、可回溯目标,全部由代码定义,不由大模型临时生成。** 注册表外的节点无法验证、无法授权、无法预估成本。
3. **默认本地跑小模型降本提速、云端兜底;一切模型均可替换(按 capability 路由)。** 没有显卡也能开箱用全部功能,只是慢一点、贵一点。
4. **spec 是唯一真源,编排逻辑不被框架锁定。** 画布、AI 生成、数据库存储的都是同一份 JSON spec;LangGraph 仅作为可替换的解释器实现之一。
5. **工作流版本不可变,运行钉住具体版本。** 编辑产生新 revision,老版本原封不动,运行结果始终可复现。
6. **进程随工作台启动而启动,随工作台关闭而关闭。**
7. **以对话为统一入口,右侧画布为其可视化;底层服务保持解耦。**
8. **服务贡献节点:接入一个服务 = 多一批节点,代码零改动。** 这是插件市场的地基。

## 总体架构

```
┌──────────────────────────────────────────┐
│ 可视化工作台层                             │
│ Electron + React Flow                     │
│ 画布、节点、流水线库、状态、日志、审批       │
│ 流程创建模式(与 AI 对话生成流水线)          │
└──────────────────────────────────────────┘
                 ↕ HTTP / WebSocket
┌──────────────────────────────────────────┐
│ 流水线引擎层                               │
│ Node.js / TypeScript                      │
│ spec 解释器(可由 LangGraph.js 实现)        │
│ 版本化、rollback、fanout/join、检查点       │
└──────────────────────────────────────────┘
                 ↕ 统一 Provider 接口
┌──────────────────────────────────────────┐
│ 模型与工具层                               │
│ ├ 本地:llama.cpp + 小模型(决策/验证/抽取)   │
│ ├ 远程:DeepSeek(编码)+ 图像/音频 API       │
│ ├ MCP + Skill + Function Call             │
│ └ 密钥托管(Electron safeStorage)          │
└──────────────────────────────────────────┘
                 ↕ WebSocket(JSON-RPC)
┌──────────────────────────────────────────┐
│ Godot 集成层                               │
│ ├ 插件:活场景树、撤销栈、视口截图、运行       │
│ ├ Headless:检查、导入、测试、导出            │
│ └ 两者按"是否需要编辑器状态"分工            │
└──────────────────────────────────────────┘
```

## 技术栈

| 层级 | 选型 |
| :--- | :--- |
| 桌面宿主 | Electron |
| 可视化画布 | React Flow |
| 流水线编排 | 自定义 spec + 解释器(首选 LangGraph.js) |
| 本地推理 | llama.cpp + Qwen2.5 / Gemma-3 小模型 |
| 远程生成 | DeepSeek(编码)+ 图像 / 视频 / 音乐 / 语音 API |
| 工具协议 | Function Call + MCP + Skill |
| Godot 集成 | EditorPlugin + Headless 双轨 |
| 持久化 | SQLite + sqlite-vec |
| 项目文件版本 | 项目自带 git |

## 实施路线

采用 **walking skeleton**(纵向打穿最险的纵切面),核心闭环三件事:**生成流程 → 执行 → 验证**。

| 轮次 | 切入 | 覆盖的风险 |
| :--- | :--- | :--- |
| **v0** | 对话 → AI 生成 spec → 校验 → 执行 → 验证 → git 每步 commit + 回退;只读画布 + 拖入单节点 | spec / 数据流 / Provider / 成本记账 / headless Godot / 验证链 / git 回退 |
| **v1** | + 小模型 verify + 人工审批 + 工作流库 / 版本化 + 手工连线 | 生成质量与门禁 |
| **v2** | + fanout 并行 + join + 多模态验证 + 全面服务接入 | 并发与 git 冲突、视觉验证 |
| **v3** | + Godot 插件 + 场景操作 + LSP/DAP + 导出打包 | 编辑器态与重型能力 |

## 状态

本项目处于**设计阶段**,技术选型与各子系统设计已定稿,正在按 walking skeleton 推进 v0 实现。
